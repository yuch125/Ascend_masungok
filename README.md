# Ascend

증상 입력 → 운동 선택 → 전체화면 카메라·실시간 MediaPipe 추적 → 촬영·자동 분석 → 기록·커뮤니티 공유를 연결한 모바일 React 웹앱입니다. 임의 측정값·회복률·게시글은 만들지 않습니다.

## 실행

```powershell
cd C:\Users\user\Desktop\startupthon\re-move
npm.cmd run dev
```

현재 의존성과 모델은 준비되어 있습니다. 새 환경에서는 npm.cmd ci를 먼저 실행하세요. Node.js 22.12 이상이 필요합니다. PowerShell에서 npm.ps1이 차단되어도 npm.cmd를 사용할 수 있습니다.

PC: http://127.0.0.1:5173

아이패드·휴대폰 실시간 카메라는 HTTPS가 필요합니다. 같은 Wi-Fi의 HTTP 주소에서는 영상 불러오기를 사용하세요. LAN 실행은 npm.cmd run dev:lan입니다. Sites 배포 설정은 .openai/hosting.json에 있습니다.

아이패드 Safari에서 HTTPS 주소를 직접 열어 카메라를 허용하세요. Safari 공유 메뉴의 ‘홈 화면에 추가’로 앱처럼 열 수도 있습니다. 세로·가로·분할 화면을 지원하며 일반 화면은 태블릿에서 최대 760px로 표시합니다. 구버전 iPadOS에서는 최신 버전으로 업데이트해야 MediaPipe Worker·영상 추론이 지원될 수 있습니다. 실제 아이패드 기기 검증은 아직 하지 못했습니다.

## 아이패드에 앱 설치

Safari에서 [Re:Move 설치 안내](https://re-move-ipad-20261024.newdegu1.chatgpt.site/?install=1)를 열고 같은 ChatGPT 계정으로 로그인하세요. 공유 → 홈 화면에 추가 → ‘웹 앱으로 열기’ 켜기(표시되는 경우) → 추가 순서로 설치합니다. 이후 홈 화면의 Re:Move 아이콘으로 실행하면 Safari 주소창 없이 열립니다. 앱 내부의 위쪽 설치 아이콘이나 더보기 → 아이패드에 앱 설치에서도 안내를 볼 수 있습니다. iPadOS는 웹페이지 버튼으로 자동 설치하는 기능을 제공하지 않아 이 과정은 사용자가 한 번 진행해야 합니다.

프로덕션 빌드에는 Web App Manifest·아이콘·Service Worker가 포함됩니다. 첫 실행은 인터넷 연결이 필요합니다. 앱 설치 후 정상적으로 내려받은 화면·코드와 기기 내 기록은 오프라인에서도 열 수 있습니다. 분석 모델·WASM은 실제 불러온 뒤 캐시되므로 처음 카메라 분석은 온라인에서 진행하세요. 로그인·계정 동기화·커뮤니티는 인터넷 연결이 필요합니다. 로그인 화면·API 응답·게시 영상은 앱 캐시에 저장하지 않습니다. 개발 서버에서는 이전 코드가 남는 것을 막기 위해 Service Worker를 등록하지 않습니다.

새 버전의 캐시 준비가 끝나면 열려 있는 Re:Move 창을 모두 닫았다 다시 열 때 업데이트됩니다. 촬영 중 앱을 강제로 새로고침하지 않습니다. iPadOS가 저장 공간을 정리하면 오프라인 캐시가 지워질 수 있습니다.

## 사용 흐름

- 첫 실행에 증상·부위·좌우 입력. 해당 부위 참고 운동을 모으며, 더보기에서 수정하면 목록이 바뀝니다. 진단·개인 처방을 생성하지 않습니다.
- 홈 중앙에 가장 최근 촬영 영상과 실제 관절·연결선·각도. 관절 표시 ON/OFF를 지원하며 원본이 없으면 측정값만 표시합니다.
- 오른쪽 위 카메라 → 운동·좌우 → 카메라 열기. 기기 내 분석 안내 후 권한을 요청하며 체크박스는 없습니다.
- 전체화면 카메라에서 녹화 전부터 실시간 관절을 표시합니다. 전면·후면·좌우 전환과 영상 불러오기를 지원합니다.
- 종료 후 자동 저장·분석. 분석 중·실패 상태에도 원본을 게시·공유·다운로드할 수 있습니다. 원본은 기본 기기 보관이며 더보기에서 끌 수 있습니다.
- 게시물 만들기에 촬영 영상 자동 첨부. 분석 항목은 선택 공개하며 게시하기 전에는 업로드하지 않습니다. 공유 파일은 원본이며 오버레이를 합성해 내보내는 기능은 없습니다.
- 트위터 스타일 커뮤니티에 글·영상·사진·좋아요·댓글·공유·필터·삭제. 로컬 데모에서는 이 기기에만 저장됩니다.
- 내 기록에서 실제 영상·분석·동일 조건 비교·그래프·JSON 내보내기·삭제. 분석 실패 영상도 재분석·공유·삭제할 수 있습니다.
- 하단 탭 홈·내 기록·커뮤니티·더보기. 일반 화면은 휴대폰 최대 440px·태블릿 최대 760px, 카메라는 전체 뷰포트입니다.
- Safari에서는 지원 여부를 확인해 MP4 녹화를 우선합니다. 명시적인 옵션이 거부되면 브라우저 기본 녹화 옵션으로 재시도합니다. 백그라운드 전환 시 촬영을 종료해 원본을 보관합니다. 사진 앱의 MOV 첨부도 지원합니다.

## 분석

공식 MediaPipe Pose Landmarker의 VIDEO 모드와 detectForVideo를 Worker에서 호출합니다. 모델·WASM은 public/models와 public/mediapipe에서 로드합니다. 분석용 영상을 외부 AI로 전송하지 않습니다.

얼굴 관련 점(코·눈·귀·입, 인덱스 0–10)은 추론 직후 Worker 안에서 제거합니다. 얼굴 좌표를 UI·저장 데이터로 전달하지 않으며 어깨 이하 신체 관절만 표시합니다. 관절 번호가 밀리지 않도록 얼굴 슬롯은 좌표 없이 null로 남깁니다. 기존 로컬 기록은 읽을 때 얼굴 좌표를 제거해 다시 저장하고, 클라우드 기록은 읽기·저장 시 같은 필터를 적용합니다. 공식 Pose 모델 내부에서는 33개 위치를 함께 추론하며 얼굴 점만 추론하지 않도록 끄는 옵션은 없습니다. 별도 Face Landmarker·Face Mesh·표정 분석은 사용하지 않습니다. 원본 영상의 얼굴을 가리는 기능과는 별개입니다.

- camera/useLivePose.ts: 열린 미리보기를 최대 약 12.5fps로 추적. 종횡비·cover 크롭·전면 미러링을 반영하며 0.5초 지난 관절은 지웁니다.
- 촬영 시각 기준으로 실제 프레임을 수집하고 종료 후 10fps 시계열로 정리합니다. 누락 구간은 null로 남깁니다. 충분한 측정이 있으면 재추론 없이 저장합니다.
- analyze.ts: 실시간 측정 부족·가져온 영상은 디코딩·길이 확인 후 0.1초 간격으로 추론합니다. WebM duration이 Infinity여도 실제 녹화 시간을 사용합니다. 탐색·Worker에 타임아웃·취소 처리가 있습니다.
- math.ts: visibility/presence 0.65 이상, 화면 내 유한 좌표와 영상 너비·높이를 반영해 2D 관절 각도를 계산합니다. 유효 측정 5개 미만 또는 전체의 25% 미만이면 결과를 만들지 않습니다.
- 최소·최대·범위·유효 비율·시계열을 저장합니다. 무릎·팔꿈치의 완결된 굽힘/펴짐 주기를 세며 0.5초 이상 누락되면 초기화합니다. 어깨 횟수는 생성하지 않습니다.

분석 버전 2d-projected-v1. 영상 0.5초–3분, 가져오기 최대 250MB, 게시 첨부 최대 20MB. 촬영은 약 800kbps를 요청하며 3분 또는 약 18MB에서 중지합니다. 실제 크기는 브라우저에 따라 달라집니다.

측정값은 표본 기반 2D 관측값으로 임상 정확도 검증·의료진 판정 연동은 구현되지 않았습니다. 같은 운동·좌우·방향·분석 버전끼리 비교합니다. 회복·정상 여부를 판정하지 않습니다.

모델·WASM이 없거나 버전을 변경하면 npm.cmd run setup:model을 실행합니다. 이 준비 과정에는 네트워크가 필요합니다. 포함된 lite 모델은 5,777,746바이트입니다. 폰트는 Google Fonts를 사용하며 실패 시 시스템 글꼴로 표시합니다.

## 저장·Supabase

개인 원본과 분석 대기·실패 메타데이터는 계정별 IndexedDB에 보관하며 기기 간 원본 동기화는 없습니다. 게시글 첨부는 개인 기록과 별개입니다. 공용 기기를 대상으로 암호화된 저장소는 아닙니다.

실제 사용자 간 커뮤니티를 연결하려면:

1. Supabase SQL Editor에서 supabase/migrations/001_initial.sql → 002_private_settings.sql → 003_ipad_media.sql 적용. 이미 적용한 마이그레이션은 건너뜁니다.
2. .env.example을 .env.local로 복사해 VITE_SUPABASE_URL과 VITE_SUPABASE_PUBLISHABLE_KEY 설정. service_role·secret 키는 사용하지 않습니다.
3. 개발 서버 재시작, Auth 서비스·리다이렉트 URL 설정 후 더보기에서 가입·로그인합니다.

증상·설정·목표·계획·분석은 RLS와 SECURITY INVOKER RPC로 동기화합니다. 로그인 시 서버 데이터를 읽고 저장 시 스냅샷을 동기화하며 다중 기기의 동시 편집 충돌 해결은 구현하지 않았습니다. 로컬 데모는 계정으로 자동 이전하지 않습니다.

게시한 첨부만 community-media 비공개 버킷에 저장합니다. 접근 가능한 가입자에게 10분 서명 URL을 발급합니다. 발급된 URL·다운로드 사본은 즉시 회수할 수 없습니다. private-videos 버킷은 향후용이며 현재 원본 업로드에는 사용하지 않습니다.

## 검증

npm.cmd run test:all / npm.cmd run build

- TypeScript·Vite 빌드 통과.
- Vitest: 각도·신뢰도·반복·비교·저장·공유·홈 영상·카메라 생명주기·실시간 추적·Worker 취소·WebM 길이·미러링·촬영 후 분석/공유·실패 재시도·Safari 녹화 형식·백그라운드 종료를 검증합니다.
- PGlite PostgreSQL 정책 테스트 7개 통과: 스키마·RPC·트랜잭션·RLS·비공개 증상·스토리지.
- 개발 서버·모델·WASM HTTP 200 확인.
- 실제 브라우저·모바일 화면·카메라·MediaPipe 추론 미검증: 연결된 브라우저가 없습니다. DOM 테스트는 하드웨어·추론 검증을 대신하지 않습니다.
- 실제 Supabase Auth·Storage 미검증: URL·공개 키가 제공되지 않았습니다. SQL 테스트는 운영 검증을 대신하지 않습니다.

수동 확인: 카메라 → 운동·좌우 → 열기 → 녹화 전 추적 → 촬영·종료 → 게시물 → 첨부·게시 → 홈 영상 → 기록·재생·삭제. 권한 거부·사람 미검출·모델 누락·전면/후면·새로고침·모바일 HTTPS도 확인해야 합니다.
